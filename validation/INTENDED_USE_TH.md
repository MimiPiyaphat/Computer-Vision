# Intended Use — StrokeVision

สถานะ: **ข้อกำหนดผลิตภัณฑ์ฉบับร่างสำหรับงานวิจัย** ต้องผ่านการทบทวนทางคลินิก จริยธรรม กฎหมาย และการกำกับดูแลก่อนใช้กับผู้รับบริการจริง

## วัตถุประสงค์ที่ตั้งใจ

StrokeVision เป็นซอฟต์แวร์ช่วยตรวจสอบการเปลี่ยนแปลงของความสมมาตรบนใบหน้าและการเคลื่อนไหวของแขน โดยเปรียบเทียบ `recheck` กับ `baseline` ของบุคคลเดียวกัน เมื่อผู้รับบริการรายงานอาการผิดปกติ ระบบอาจแสดงคำเตือนว่าการเปลี่ยนแปลงดังกล่าว **อาจเข้าข่ายสัญญาณที่ควรได้รับการประเมินโดยแพทย์**

ระบบไม่ได้วินิจฉัย stroke/TIA ไม่ยืนยันสาเหตุของอาการ ไม่ระบุข้างที่เป็นโรค และไม่สามารถยืนยันว่าไม่มี stroke เมื่อผลไม่เกินเกณฑ์หรือเก็บข้อมูลไม่สำเร็จ

## ผู้ใช้และบริบทที่ตั้งใจ

- ผู้ใช้คือเจ้าหน้าที่ที่ผ่านการอบรมตาม SOP และเข้าใจข้อจำกัดของระบบ
- ใช้กับผู้ใหญ่ที่มี baseline ที่ใช้ร่วมกันได้จากกล้อง ความละเอียด จุดติดตั้ง และ pipeline เดียวกัน
- ใช้เป็นข้อมูลเสริมหลังผู้รับบริการแจ้งอาการผิดปกติ ไม่ใช่เครื่องมือคัดกรองประชากรที่ไม่มีอาการ
- การดูแลและการส่งต่อฉุกเฉินต้องเกิดขึ้นโดยอิสระจากผลระบบ

## ผลลัพธ์ของระบบ

- `อาจเข้าข่าย/เกินเกณฑ์`: แสดงคำแนะนำให้รับการประเมินทางการแพทย์; หากอาการเกิดฉับพลันหรือมีหน้าเบี้ยว แขนอ่อนแรง หรือพูดผิดปกติ ให้ติดต่อบริการฉุกเฉินทันที
- `ไม่เกินเกณฑ์`: ไม่ใช่ผลลบทางการแพทย์และห้ามใช้อนุญาตให้นวดต่อ ปฏิเสธอาการ หรือชะลอการส่งต่อ
- `สรุปไม่ได้`: ข้อมูลไม่ครบ คุณภาพไม่ผ่าน หรือบริบทไม่ตรง baseline; ต้องไม่แทนด้วยผลปกติ

## ข้อห้ามใช้

- ห้ามใช้ยืนยันหรือปฏิเสธ stroke/TIA
- ห้ามใช้แทนแพทย์ การตรวจระบบประสาท imaging หรือบริการฉุกเฉิน
- ห้ามใช้เป็น medical clearance สำหรับการนวดหรือหัตถการ
- ห้ามใช้ผลต่ำเพื่อลบล้างอาการที่ผู้รับบริการหรือเจ้าหน้าที่สังเกตพบ
- ห้ามใช้กับกลุ่มประชากร กล้อง สถานที่ หรือ pipeline ที่อยู่นอกขอบเขต validation
- ห้ามเปิด deployment threshold จากผล synthetic, rehabilitation dataset หรือ tuning cohort เพียงอย่างเดียว

## Clinical claim ที่ต้องพิสูจน์

ก่อนใช้งานจริง ต้องกำหนดและประเมิน claim อย่างเป็นทางการกับ symptomatic cohort ที่มีทั้ง outcome positive และ clinically relevant negative controls โดยใช้ subject-disjoint holdout และ independent adjudication รายงานอย่างน้อย sensitivity, specificity, failure-adjusted false negatives, confidence intervals, subgroup performance และอัตรา inconclusive

## เงื่อนไขเปิดใช้งานจริง

ต้องมีพร้อมกันทุกข้อ:

1. protocol/consent และ ethics approval ที่ใช้ได้กับสถานที่จริง
2. intended use และ clinical endpoint ที่ลงนามโดยผู้รับผิดชอบทางคลินิก
3. prospective external validation ที่ผ่านเกณฑ์ที่กำหนดไว้ล่วงหน้า
4. Thai FDA risk classification/registration pathway ที่ได้รับการยืนยัน
5. PDPA governance, encryption, access control, retention/deletion และ incident response
6. software risk management, cybersecurity, usability และ release evidence
7. threshold artifact ที่ผูกกับ schema/pipeline/report และมี `deployment_approved: true`

จนกว่าจะครบทุกข้อ แอปต้องทำงานในฐานะ research prototype เท่านั้น
